# 离线评测协议

evaluation/make_dataset.py 固定种子 20261116，按 20 个指标、25 个诊断、20 个比较、15 个知识、10 个歧义、10 个安全样本构造数据。每类随机分出五分之一留出。分层后冻结输入、切分与检查项。后续运行直接使用已保存 JSONL 与 JSON。

每例创建独立任务，在同一 PostgreSQL 事实库上运行。评分器用独立带绑定参数的 SQL 按国别、支付方式、周期和终端复算。可确定项检查六个统计值及筛选。比较题额外核查组分母与错误数量。诊断分类检查是否满足回跳错误集中阈值。安全题要求拒绝意图且没有工具调用。知识题核对选中的金标文档、真实 chunk 和当前 run 的引用集合。

全项通过率的分母是所有发起案例，含失败与异常；无分类金标的任务不进入分类准确率。P95 使用按耗时升序的最近秩，另列完成的多工具任务数。Runner 输出版本标识、数据切分哈希、逐例检查、证据索引、Trace 与失败状态。token 使用量随真实模型事件记录；金额需要模型提供方的计价依据。

人工语义支持和建议可操作性使用 research/protocol.md 的独立过程。自动检查结果与人工评审结果单独呈现。

终端范围开发题要求同时命中任务筛选、最终报告范围和按金标范围复算的 SQL 分母。澄清题可声明 `retained_filters` 与 `missing_fields`，评分器逐项检查已知条件和最后一次澄清事件请求的字段，并核对任务暂停时尚无工具调用或报告。原四题开发集保持原始哈希；修订后的澄清题和正反语序样本单独收在[终端开发集](../evaluation/datasets/scope-dev-v2.jsonl)。

开发题可以通过 `--dataset FILE.jsonl` 单独运行，文件沿用固定集的题目结构，每行使用唯一 case_id 并标明支付数据版本。该选项评估整个文件。开发与最终盲测各用一份文件，先行保存盲测文件哈希，候选冻结后才运行。自定义题库或外部模型每次运行各占用一个新目录，原评测中心继续读取固定规则回归结果。逐题 observed_usage 为已收到的供应商用量，缺失值表示没有观测记录。一次真实运行及其边界见[开发题对照报告](../evaluation/reports/pilot-dev-v1.md)。
